# TESTING.md — Руководство тестировщика

## Проект

Telegram Mini App для бьюти-мастера Дарьи Русаковой (г. Гомель). SPA на чистом JS без фреймворков. Записи хранятся в `localStorage`, реальной базы данных нет.

---

## 1. Быстрый старт

### Требования

- Python 3 **или** любой локальный HTTP-сервер
- Современный браузер (Chrome / Firefox / Safari / Edge)

### Запуск

```bash
cd tg-app
python -m http.server 8080
```

Открыть: `http://localhost:8080`

> **Важно:** открывать через HTTP-сервер, а не через `file://` — иначе межпроцессные запросы могут блокироваться CORS-политикой браузера.

### Сброс состояния

Добавить `?reset` к URL:

```
http://localhost:8080?reset
```

Это выполняет `localStorage.clear()` и перезагружает страницу без параметра (см. `app.js:1614–1617`). Использовать перед каждым прогоном тест-кейса «с чистого листа».

## 3. Ограничения браузера

Telegram SDK не активен вне Telegram. Следствия:

| Функция Telegram | Поведение в браузере |
|-----------------|---------------------|
| `tg.MainButton` | **Не отображается** |
| `tg.BackButton` | **Не отображается** |
| `tg.showConfirm` | `window.confirm` (стандартный браузерный диалог) |
| `tg.openTelegramLink` | `window.open(url, '_blank')` |
| `tg.openLink` | `window.open(url, '_blank')` |
| `tg.switchInlineQuery` | `navigator.share` → если нет, копирует ссылку в буфер |
| Имя пользователя | «Гость» |

**Критично для тестирования:** на экране «Календарь» у `MainButton` нет браузерного резервного аналога (подробнее — в разделе «Баги»).

## 6. Найденные баги

### BUG-01 — Экран деталей записи всегда пустой

**Серьёзность:** Высокая  
**Файл:** [tg-app/js/app.js](tg-app/js/app.js)  
**Воспроизведение:**
1. Сделать запись
2. Открыть вкладку «Записи»
3. Нажать на карточку записи

**Ожидаемо:** Экран с деталями записи (дата, время, адрес, кнопки действий).  
**Фактически:** «Запись не найдена».

**Причина:** В обработчике клика (строка ~1336) `bookingId` читается из `el.dataset.bookingId` как **строка**. В `renderBookingDetail` (строка ~835) сравнение `x.id === bookingId` использует строгое равенство. Но `x.id` — **число** (результат `Date.now()`), сохранённое и восстановленное через JSON. Строгое сравнение строки и числа всегда `false`.

**Исправление** в `app.js`, блок `case 'go-booking-detail'`:

```js
// Было:
const bookingId = el.dataset.bookingId;

// Стало:
const bookingId = Number(el.dataset.bookingId);
```

### BUG-02 — Лайтбокс уничтожает кнопки после первого открытия

**Серьёзность:** Средняя  
**Файл:** [tg-app/js/app.js](tg-app/js/app.js)  
**Воспроизведение:**
1. Открыть карточку любой услуги
2. Нажать на слайд галереи
3. Попробовать нажать X (закрыть) — кнопки нет

**Ожидаемо:** Лайтбокс с кнопкой «✕», счётчиком «1 / 3», навигацией ‹ ›.  
**Фактически:** Чёрный экран с эмодзи, кнопки закрытия и навигации пропадают. Закрыть можно только кликом по затемнённому overlay.

**Причина:** `updateLightbox()` (строка ~1439) перезаписывает `.innerHTML` элемента `.lightbox-content`, уничтожая кнопки закрытия, счётчик и навигацию, которые находятся внутри этого же элемента согласно `index.html`. При повторном вызове `updateLightbox` (свайп) происходит `TypeError: Cannot set properties of null` — поиск `.lightbox-counter` возвращает `null`.

**Исправление** в `app.js`, функция `updateLightbox`:

```js
// Было — перезаписывало всё содержимое .lightbox-content:
lb.querySelector('.lightbox-counter').textContent = `${State.lightboxIndex + 1} / ${State.lightboxPhotos.length}`;
lb.querySelector('.lightbox-content').innerHTML = `
  <div class="lightbox-emoji" ...>${p.emoji}</div>
  <div class="lightbox-label">${p.label}</div>`;

// Стало — обновлять только конкретные элементы:
document.getElementById('lightbox-counter').textContent =
  `${State.lightboxIndex + 1} / ${State.lightboxPhotos.length}`;
document.getElementById('lightbox-photo').innerHTML =
  `<div class="lightbox-emoji" style="filter:drop-shadow(0 4px 12px rgba(0,0,0,.5))">${p.emoji}</div>
   <div class="lightbox-label">${p.label}</div>`;
```

Элемент `#lightbox-photo` уже существует в `index.html` (строка 62) и не содержит кнопок навигации — его безопасно перезаписывать.

> **Примечание:** обработчики `lightbox-prev` и `lightbox-next` в `switch(action)` отсутствуют — после исправления innerHTML кнопки ‹ › будут видны, но нажатие на них ничего не сделает. Навигация работает только свайпом. Можно оставить как есть или добавить обработчики.

### BUG-03 — В браузере нет кнопки «Продолжить» на экране Календарь

**Серьёзность:** Высокая (полностью блокирует тестирование бронирования в браузере)  
**Файл:** [tg-app/js/app.js](tg-app/js/app.js) — функция `renderCalendar`  
**Воспроизведение:**
1. Открыть любую услугу, нажать «Выбрать время»
2. Выбрать дату
3. Выбрать временной слот

**Ожидаемо:** Появляется кнопка «Продолжить» → переход на «Сводку».  
**Фактически:** В браузере кнопка не появляется. `tg.MainButton` не работает вне Telegram. Резервной HTML-кнопки в `renderCalendar` нет (в отличие от экранов «Услуга» и «Сводка», где резервные кнопки есть).

**Временный обходной путь для тестирования:**
Открыть DevTools → Console и выполнить:
```js
Router.go('summary', {});
```
(Работает только если `State.selectedDate` и `State.selectedTime` уже установлены.)

**Исправление** — добавить в `renderCalendar` резервную кнопку внутри `#slots-container` или сразу под ним. Кнопку показывать только после выбора слота через JS:

В обработчике `select-slot` (строка ~1246) добавить после показа MainButton:
```js
// Резервная кнопка для браузера
const fallback = document.getElementById('calendar-continue-btn');
if (fallback) fallback.style.display = 'flex';
```

В `renderCalendar` добавить скрытую кнопку после `#slots-container`:
```html
<div style="padding:16px var(--px) 0; display:none" id="calendar-continue-fallback">
  <button class="btn-primary" id="calendar-continue-btn"
          data-action="calendar-go-summary">
    Продолжить
  </button>
</div>
```

В обработчике событий добавить кейс:
```js
case 'calendar-go-summary': {
  if (State.selectedDate && State.selectedTime) {
    Router.go('summary', {});
  }
  break;
}
```
