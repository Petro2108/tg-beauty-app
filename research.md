## 1. Пять ключевых примеров TMA

### 1.1 NAMB
**Сайт:** namb.pro  
**Что делает:** Telegram Mini App для онлайн-записи в салонах красоты, клиниках и сервисных компаниях. Глубокая интеграция с YClients и другими профессиональными CRM. Брендированный мини-сервис — каждый бизнес получает свой экземпляр с собственным оформлением.

#### Сильные стороны
- Глубокая интеграция с YClients — данные о расписании синхронизируются в реальном времени
- Брендирование под конкретный бизнес: логотип, цвета, название
- Высокая конверсия: минимум шагов от выбора до подтверждения записи
- Целевая аудитория салонов с несколькими мастерами хорошо охвачена

#### Слабые стороны
- Жёсткая зависимость от сторонних CRM — без YClients не работает полноценно
- Нет каталога товаров, только услуги
- Интерфейс заточен под салоны с персоналом, неудобен для одного мастера
- Нет портфолио работ в карточке услуги/мастера
- Нет встроенных напоминаний (делегируется CRM)

#### Что мы можем сделать лучше
- Сделать standalone-версию без зависимости от CRM
- Добавить галерею работ прямо в карточку мастера
- Упростить flow для одного мастера (убрать лишний экран "выбор мастера")
- Встроить автоматические напоминания через Telegram-бота

---

### 1.2 YLine
**Что делает:** TMA для автоматизации записи клиентов в сервисных бизнесах. Позволяет онлайн-бронировать время, просматривать меню услуг, получать уведомления и напоминания. Акцент на снижении ручного труда мастера.

#### Сильные стороны
- Сквозная автоматизация: от бронирования до напоминаний
- Централизованное управление клиентами и расписанием
- Снижает нагрузку на мастера по коммуникации
- Бесплатные Telegram-уведомления вместо SMS

#### Слабые стороны
- Ограниченная кастомизация под конкретный бренд
- Нет витрины товаров — только услуги
- Нет аналитики по продажам и популярности услуг
- Интерфейс функциональный, но не эмоциональный — для бьюти это минус

#### Что мы можем сделать лучше
- Добавить визуально сильный дизайн под бренд мастера
- Интегрировать витрину товаров (косметика, средства ухода)
- Добавить аналитику: популярные услуги, загрузка мастера, выручка
- Mood-board оформление для атмосферы

---

### 1.3 SalonBot
**Что делает:** Open-core система бронирования, работающая полностью внутри Telegram. Поддерживает расписание нескольких сотрудников, админ-панель, аналитику и интеграцию с оплатой. Self-hosted — бизнес владеет всеми данными. Без ежемесячной подписки.

#### Сильные стороны
- Полный контроль над данными (не SaaS, нет vendor lock-in)
- Решает реальную проблему: пропущенные сообщения и двойные бронирования
- Единый бэкенд для бота и Mini App
- Нет ежемесячной платы — разовая установка

#### Слабые стороны
- Требует технических знаний для установки и обслуживания
- Нет витрины товаров
- Клиентский интерфейс не интуитивен — заточен под администраторов
- Нет облачной версии для нетехнических мастеров

#### Что мы можем сделать лучше
- SaaS-версия без необходимости хостинга (главный барьер для мастеров)
- Готовые шаблоны оформления без кодинга
- Упрощённый клиентский интерфейс с фокусом на клиенте, а не администраторе
- Добавить витрину товаров

### 1.4 Listbook
**Сайт:** listbook.app  
**Что делает:** Система онлайн-записи через Telegram Mini App. Подходит для мастеров, студий и сервисных бизнесов. Клиент выбирает услугу, время и записывается без звонков.

#### Сильные стороны
- Очень простой onboarding — пользователь сразу понимает что делать
- Минимум отвлечений: интерфейс фокусируется на услуге, времени и подтверждении
- Хорошая мобильная UX: крупные кнопки, хорошая читаемость, минимум текста
- Быстрый старт для мастера

#### Слабые стороны
- Слабая эмоциональность — для бьюти выглядит слишком "системным"
- Мало визуального контента: нет фото работ, нет атмосферы, нет портфолио
- Нет ощущения бренда мастера — выглядит универсально
- Нет социального доказательства (отзывы, рейтинг)

#### Что мы можем сделать лучше
- Добавить gallery before/after прямо в карточку услуги
- Персонализированный дизайн под бренд мастера
- Отзывы клиентов с фото
- Mood-board оформление в духе Instagram/Pinterest

### 1.5 Teleport (конструктор)
**Сайт:** findmini.app/teleportappbot  
**Что делает:** Конструктор магазинов и сервисных приложений внутри Telegram без программирования. Поддерживает услуги, товары, бронирования и оплату. Универсальный инструмент — не заточен под бьюти.

#### Сильные стороны
- Не требует навыков программирования — настройка за 15 минут
- Универсальность: подходит и для товаров, и для услуг
- Бесплатный пробный период
- Уведомления о новых заказах прямо в Telegram
- Хорошая e-commerce UX: каталог → корзина → заказ → оплата

#### Слабые стороны
- Общее решение без бьюти-специфики: нет calendar занятости мастера, нет галереи работ
- Ограниченная кастомизация в бесплатной версии
- Функционал для услуг развит слабее, чем для товаров
- Нет storytelling, нет атмосферы, нет персональности

#### Что мы можем сделать лучше
- Бьюти-специфичный шаблон с календарём, портфолио, прайс-листом из коробки
- Акцент на мастере как личности, а не безликом каталоге
- Интеграция calendar занятости с блокировкой двойных записей
- Больше воздуха, крупнее изображения, стиль Instagram

## 2. Общий анализ рынка

### Вывод из 14 проанализированных приложений

Рынок Telegram Mini Apps в бьюти-нише **активно развивается, но не насыщен** качественными решениями для индивидуальных мастеров.

Существующие решения делятся на три категории:

| Тип | Примеры | Проблема |
|---|---|---|
| Для крупных салонов с CRM | NAMB, SalonBot | Избыточны для одного мастера, требуют YClients или технических знаний |
| Универсальные конструкторы | Teleport, Botami | Нет бьюти-специфики, нет эмоций, нет атмосферы |
| Только товары (без записи) | BEAUTY KOREAN | Не закрывают потребность мастера в записи клиентов |

**Незанятая ниша:** легковесное TMA для одного мастера с записью + витриной + портфолио.

### Главная проблема рынка: Discoverability

По данным Reddit-обсуждений (r/Telegram, r/TelegramBots): пользователи плохо находят Mini Apps. Нет органики внутри Telegram. Нужно вести трафик из:
- Telegram-канала мастера
- Instagram / TikTok
- Таргетированной рекламы

Это **возможность**: тот, кто умеет продвигать — займёт нишу первым.

## 4. Обязательные элементы интерфейса

### Навигация
- **Bottom navigation bar** — 3–4 таба: Главная, Каталог, Записи, Профиль
- **BackButton** Telegram — обязателен на каждом подэкране (`Telegram.WebApp.BackButton`)
- **MainButton** (Telegram) — использовать для primary action: "Записаться", "Подтвердить", "Оплатить"

### Карточки услуг
- Фото, название, цена, длительность, рейтинг + краткое описание
- Горизонтальный скролл для "Популярных" и "Рекомендаций"
- Вертикальный список для каталога и поиска
- **Skeleton loaders** вместо спиннеров — снижает perceived latency

### Фильтры и поиск
- Sticky filter chips (не выпадающие меню): по категории, цене, длительности
- Поиск — instant (debounced), не "отправить по кнопке"
- Переключатели "Доступно сегодня" и "Сначала популярные" — highest conversion filters

### Календарь / выбор времени
- Месячный вид с точками на доступных днях (не generic date picker)
- Тап по дню → сетка временных слотов
- Цветовая схема: доступные (белый), выбранный (accent), занятые (серый зачёркнутый)
- Показывать "Следующий доступный: Сегодня в 15:00" прямо на карточке услуги

### Подтверждение бронирования
- Sticky bottom bar с итоговой ценой + MainButton "Подтвердить"
- Редактируемые строки (тап → вернуться к выбору)
- Политика отмены — ДО подтверждения, не после

## 5. Что нас убьёт vs что даст конверсию

### Убивает конверсию (drop-off причины)

| Проблема | Потеря пользователей |
|---|---|
| Больше 3 тапов от карточки до слота | ~15–20% на каждый лишний экран |
| Обязательная регистрация до показа услуг | Большинство уйдут — Telegram уже знает кто пользователь |
| Цена скрыта до последнего экрана | Главный триггер drop-off в бьюти |
| Медленная загрузка фото услуг | Бьюти-приложения фото-тяжёлые, нужен lazy load + WebP |
| Календарь без индикации доступности | Пользователи тапают каждый день и уходят |
| Нет социального доказательства на странице решения | Без рейтинга и 2–3 отзывов выше fold не записываются |
| Сломанная кнопка "Назад" | Пользователи закрывают всё приложение |
| Редирект на внешний сайт для оплаты | ~40% drop — использовать Telegram Payments API |

### Даёт конверсию (conversion drivers)

| Механика | Эффект |
|---|---|
| Кнопка "Записаться снова" | Повторные записи — самый высококонверсионный action |
| "Следующий доступный: Сегодня 15:00" прямо на карточке | Убирает необходимость открывать календарь |
| Прогресс-индикатор flow (Шаг 1/3) | Снижает abandon в середине flow на ~25% |
| Telegram-бот напоминания (за 24ч и 2ч) | Снижает no-show и укрепляет доверие |
| Отзывы с фото реальных клиентов | Конвертируют в 3× лучше, чем текстовые |
| One-tap re-booking из "Мои записи" | Возвращает клиентов без усилий |

## 6. Telegram-специфика: ограничения и возможности

### Ограничения (нужно учесть)

| Ограничение | Что делать |
|---|---|
| Нет push-уведомлений из WebApp | Использовать Telegram-бот того же бота для напоминаний |
| Высота viewport меняется при открытии клавиатуры | Использовать `Telegram.WebApp.viewportStableHeight` |
| Нет надёжного swipe-to-go-back на iOS | Всегда показывать BackButton через API |
| Тема цветов наследуется из Telegram | Читать `colorScheme` и `themeParams`, поддерживать оба режима |
| Ограниченный local storage | Пагинировать агрессивно, кэшировать только критичное |

### Возможности (использовать обязательно)

| Возможность | Как использовать |
|---|---|
| User identity pre-filled | `initDataUnsafe.user` — имя, фамилия, аватар. Предзаполнять формы, персонализировать приветствие |
| Haptic feedback API | `HapticFeedback.impactOccurred()` на подтверждение записи — ощущение native |
| MainButton | Всегда-видимый CTA без CSS `position: fixed` (ломается с клавиатурой) |
| Telegram Payments | In-app оплата без редиректа — снижает friction |
| Bot + Mini App unified | Бот присылает "Через 1 час ваша запись" с кнопкой, открывающей детали в Mini App |
| `expand()` на старте | Всегда вызывать `Telegram.WebApp.expand()` для полноэкранного режима |
| Share button | Поделиться карточкой услуги или мастера в чат |

### Технические требования для бьюти Mini App

- **Шрифт:** системный (`-apple-system`, `Roboto`) — кастомный шрифт = +200ms latency
- **Touch targets:** минимум 44×44px
- **Bottom safe area:** `env(safe-area-inset-bottom)` для iPhone home indicator
- **Skeleton UI** в течение 1 секунды после открытия
- **Формат изображений:** WebP с lazy loading, превью thumbnail

## 7. Что мы можем сделать лучше конкурентов

На основе анализа всех 14 рассмотренных приложений:

### 1. Объединить запись + витрину + портфолио в одном TMA
Ни один конкурент не делает это хорошо для одного мастера. Либо только запись, либо только товары.

### 2. "Мастер как личность", не безликий каталог
Конкуренты показывают услуги. Мы должны продавать мастера. Большое фото, история, специализация, ценности — это строит доверие, которое в бьюти важнее цены.

### 3. Gallery before/after прямо в карточке услуги
Ни один из проанализированных конкурентов не делает это удобно. А именно это — главный конверсионный элемент для бьюти.

### 4. Умный календарь (не generic date picker)
Показывать доступность прямо на карточке услуги. Месячный вид с точками. "Следующий слот: сегодня в 15:00" — одним тапом.

### 5. Встроенные напоминания без CRM
YLine и NAMB делают это через внешние системы. Мы — через родной Telegram-бот, бесплатно.

### 6. Лёгкий старт без технических знаний и без внешней CRM
SalonBot — self-hosted (нужен DevOps). NAMB требует YClients. Teleport — слишком универсален. Наш продукт: мастер регистрируется, добавляет услуги, начинает принимать записи за 10 минут.

### 7. Дизайн в духе Instagram/Pinterest, а не корпоративного CRUD
Все конкуренты выглядят как системы управления. Бьюти-мастер хочет показать атмосферу. Большие изображения, воздух, premium-feel.

### 8. Реферальная программа
Ни у одного конкурента нет встроенной реферальной механики. Бонус за приглашение = органический рост.

## 8. Архитектура экранов (рекомендация)

```
Запуск → expand() →

TAB 1: Главная
├── Персонализированное приветствие (имя из Telegram)
├── Фото мастера + USP
├── "Записаться снова" (карточка для возвращающихся клиентов)
├── Категории услуг (Hair / Nails / Skin / Brows / Makeup)
└── Популярные услуги (вертикальные карточки)

TAB 2: Каталог
├── Filter chips (sticky): категория, цена, длительность
├── Список услуг с фото + цена + рейтинг
└── Карточка услуги → Gallery → Отзывы → Выбор даты → Сводка → Подтверждение

TAB 3: Мои записи
├── Вкладка "Предстоящие"
├── Вкладка "Прошлые"
└── Детали записи → Перенести / Отменить / Записаться снова

TAB 4: Профиль мастера (облегчённый)
├── Данные из Telegram (предзаполнены)
├── Избранные услуги
└── Настройки уведомлений

BOOKING FLOW (modal / отдельный stack):
  Шаг 1/3: Карточка услуги + Gallery
  Шаг 2/3: Календарь → Выбор слота
  Шаг 3/3: Сводка (MainButton = "Подтвердить запись")
  Шаг 4: Оплата (Telegram Payments, если применимо)
  Шаг 5: Success screen + "Поделиться" + "Добавить напоминание"
```

## Ключевые метрики для валидации продукта

| Метрика | Плохо | Хорошо | Отлично |
|---|---|---|---|
| Booking completion rate (от просмотра услуги до подтверждения) | < 15% | 18–25% | > 35% |
| Время до первой записи | > 3 мин | 90 сек | < 60 сек |
| Повторная запись в течение 30 дней | < 20% | 30–40% | > 50% |
| Drop-off на шаге "Календарь" | > 50% | 30–40% | < 20% |

### Незанятые ниши (стратегические пробелы)

На основе анализа всех конкурентов выделяются 5 чётких возможностей:

1. **Brand-first booking** — мастера хотят своё имя/бренд на Mini App, а не "Botami" или "Listbook". White-label по доступной цене — никто не делает хорошо.

2. **Discovery + booking в одном нативном TMA** — Listbook имеет discovery, но web-heavy. Никто не делает полностью нативный Telegram Mini App маркетплейс такого же уровня.

3. **Механики лояльности и повторных клиентов** — штампы, реферальные вознаграждения, кэшбэк за повторные визиты. Ни у одного конкурента нет нативно.

4. **Портфолио/галерея работ внутри booking flow** — клиенты хотят видеть работы мастера до записи. Все конкуренты делают это как afterthought.

5. **Прозрачное ценообразование** — бесплатный tier как ловушка — распространённая жалоба у всех игроков. Честная и простая цена = доверие.

## 10. Экспертная оценка

> Идея: каталог услуг бьюти-мастера как Telegram Mini App.
> Оценка проведена с трёх независимых точек зрения на основе данных исследования.

---

### 10.1 Точка зрения UX-дизайнера

#### Типичные ошибки новичков в этой нише

**1. Архитектура "по логике мастера, а не клиента"**
Новички строят каталог так, как удобно им его наполнять: "Маникюр", "Педикюр", "Брови" — плоский список. Клиент думает иначе: "хочу что-то нарядное на руки к выходным". Навигация должна строиться от задачи клиента, а не от классификатора услуг.

**2. Слишком много информации на главном экране**
Hero-экран перегружают: акции, новинки, категории, кнопки соцсетей, баннеры. Взгляд не знает, куда идти. В бьюти одна задача на главном экране — вызвать желание и дать понятный следующий шаг. Всё остальное — лишнее.

**3. Форма записи как анкета**
Просят имя, фамилию, телефон, email, пожелания — до того как клиент увидел хоть одну работу мастера. Telegram уже знает имя и контакт. Нужно только подтверждение.

**4. Галерея как отдельный раздел, оторванный от услуги**
Клиент смотрит на маникюр → хочет увидеть примеры маникюра → его отправляют в отдельный раздел "Портфолио", где всё вперемешку. Связь "услуга → примеры этой услуги" должна быть прямой.

**5. Скрытые цены или диапазоны "от XXX₽"**
"От 800 рублей" — главный раздражитель в бьюти. Клиент записывается ментально на 800, а на приёме узнаёт что нужное ему стоит 2500. Доверие разрушено. Указывай точную цену или честный диапазон с объяснением.

**6. Кнопка "Назад" ведёт не туда**
В Telegram Mini App кнопка назад в шапке браузера и `BackButton` из Telegram SDK — разные вещи. Новички забывают настраивать `BackButton` на каждом экране. Пользователь нажимает системную кнопку — приложение закрывается. Конец сессии.

**7. Анимации и переходы тормозят**
Новички добавляют красивые fade-in, slide-up, parallax. В Telegram WebView на бюджетных Android это всё рендерится в 10fps. Пользователь думает что приложение зависло.

---

#### Что обязательно должно быть (UX must-haves)

**Доверие до первого тапа на "Записаться"**
- Фото мастера крупно — не логотип, не узор, а живой человек
- 2–3 отзыва реальных клиентов с именем и фото работы — прямо на главном экране
- Количество выполненных работ или лет опыта — один факт, не список достижений

**Визуальная связь услуга → результат**
- Каждая карточка услуги должна иметь минимум 2–3 фото реальных работ
- Формат before/after — самый конверсионный в бьюти: показывает трансформацию
- Видео-пример (10–15 секунд) — если есть, конвертирует лучше фото

**Время и цена — всегда видны**
- На карточке услуги: цена и длительность не меньше 16px, не под fold
- На экране выбора времени: итоговая стоимость видна без скролла
- На сводке: нет скрытых комиссий и "уточняйте у мастера"

**Моментальный feedback на каждое действие**
- Тап по слоту → слот визуально выделился + haptic vibration
- Подтверждение записи → полноэкранный success state, не просто тост-уведомление
- Ожидание ответа сервера → skeleton, не пустой белый экран

**Пустые состояния с выходом**
- "Нет свободных слотов на этой неделе" → кнопка "Посмотреть следующую неделю"
- "Нет услуг в этой категории" → кнопка "Посмотреть все услуги"
- Никогда не оставляй пользователя в тупике без следующего шага

---

#### Что бесит пользователей (топ жалоб из анализа конкурентов)

| Раздражитель | Почему критично |
|---|---|
| Медленная загрузка фото | Первые 2 секунды — решение "остаться или уйти". Бьюти = много фото |
| "Уточните цену у мастера" | Воспринимается как развод. Клиент уходит к тому, у кого указана цена |
| Нельзя отменить запись внутри приложения | Клиент пишет в личку, мастер не отвечает. Следующий раз не записывается онлайн |
| Переход на сайт для оплаты | Новый браузер, нужно вводить данные карты — 40% бросают |
| Нет подтверждения на почту/в Telegram | Страх "а вдруг не записался" → дублирующий звонок мастеру |
| Приходится скролить 3 экрана до кнопки "Записаться" | CTA должен быть доступен без скролла |

### 10.2 Точка зрения маркетолога

#### Что заставит записаться: психология решения в бьюти

Клиент бьюти-мастера принимает решение **эмоционально, а рационализирует потом**. Это означает: первично работают образы и доверие, вторично — цена и удобство.

Путь клиента в Mini App: увидел → захотел → убедился → записался. Задача каждого экрана — не потерять на своём шаге.

---

#### Элементы, повышающие конверсию

**1. Социальное доказательство в правильном месте**

Отзыв работает не на странице "Отзывы" — туда никто не ходит. Он работает прямо на карточке услуги, между фото и кнопкой "Записаться". Формат: фото клиента (или работы) + имя + 1 предложение. Длинные тексты не читают.

Счётчик записей ("сделала 347 маникюров") или "ближайший слот: завтра 14:00" — оба работают как social proof и urgency одновременно.

**2. Визуальный якорь "до/после"**

Before/after — самый сильный конверсионный формат в бьюти. Показывает не просто результат, а трансформацию. Клиент проецирует себя на фото "после". Конверсия с before/after в среднем на 30–60% выше, чем с фото только результата.

Внедрять в: карточку каждой услуги + hero-экран (самая яркая трансформация мастера).

**3. Принцип "следующий шаг всегда очевиден"**

На каждом экране — одно главное действие. Не три кнопки одного размера. Иерархия: primary CTA (крупная, акцентная) → secondary (текстовая ссылка). Пользователь не должен думать "что нажать".

Telegram MainButton — идеальный инструмент: он один, он внизу, он всегда видим.

**4. Urgency без агрессии**

"Ближайший свободный слот: завтра, 11:00" — мягкая urgency. Клиент видит, что мастер востребован, но ещё можно записаться.

"ОСТАЛОСЬ 2 МЕСТА!!!" — агрессивная urgency. В бьюти не работает, разрушает атмосферу доверия.

Хорошо: показывать реальную занятость. Плохо: искусственно создавать дефицит.

**5. Персонализация через Telegram**

Telegram передаёт имя пользователя. Использовать:
- "Привет, Анна! Посмотри, что нового у Марины" (главный экран)
- "Анна, ваша запись подтверждена" (success screen)
- "Анна, через 2 часа маникюр у Марины" (бот-напоминание)

Персонализация повышает open rate напоминаний на 20–35% и снижает no-show.

**6. Реферальная механика как встроенный маркетинг**

Лучший момент для реферального предложения — сразу после успешной записи (success screen). Клиент находится в точке максимального позитивного эмоционального состояния.

Формат: "Запишите подругу — получите скидку 200₽ на следующий визит". Кнопка "Поделиться" открывает Telegram-шару с персональной ссылкой.

Экономика: стоимость привлечения через реферал = 200₽ скидка. Стоимость привлечения через таргет = 300–800₽. Реферал выгоднее и конвертирует теплее.

**7. Программа лояльности как причина возвращаться**

Самая простая механика — штамп-карта: 5 визитов → 6-й со скидкой. Видна на главном экране у возвращающегося клиента. Создаёт причину записаться именно здесь, а не перейти к другому мастеру.

Реализация: прогресс-бар "4 из 5 визитов" на главном экране для клиентов с историей.

---

#### Что НЕ повышает конверсию (популярные заблуждения)

| Заблуждение | Реальность |
|---|---|
| "Добавим баннер с акцией на главную" | Баннеры игнорируются (banner blindness). Работают встроенные карточки с конкретной ценой |
| "Сделаем поп-ап при входе" | Pop-up при открытии = немедленное закрытие Mini App |
| "Добавим как можно больше услуг" | Длинный нефильтруемый список снижает конверсию. Работает "5 популярных" + поиск |
| "Покажем все отзывы на отдельной странице" | Страница отзывов не открывается. Нужно встраивать 2–3 в ключевые экраны |
| "Сделаем splash screen с логотипом" | Задержка старта = потеря пользователей. Telegram и так показывает loading |

### 10.3 Точка зрения Telegram-разработчика

#### Ограничения, о которых нужно знать до начала разработки

**1. Mini App — это не мобильное приложение, это веб-страница в WebView**

Всё, что плохо работает в мобильном браузере, плохо работает и в Mini App. CSS `position: fixed` ломается при открытии клавиатуры. `100vh` не равен реальной высоте viewport. Нет доступа к нативным API устройства (кроме тех, что предоставляет Telegram SDK).

Правило: тестировать на реальных Android-устройствах среднего сегмента (Xiaomi Redmi, Samsung A-series) — именно там живёт целевая аудитория мастеров.

**2. Нет push-уведомлений из WebApp**

Mini App не может присылать уведомления самостоятельно. Все напоминания — через Telegram-бота. Архитектурное следствие: бот и Mini App должны быть частью одного проекта с общим бэкендом с самого начала, не "добавим потом".

**3. Telegram Payments — не во всех регионах**

Telegram Payments работают через провайдеров (Stripe, ЮKassa, Тинькофф и др.). В ряде регионов СНГ — ограничения. Нужно проверить доступность выбранного провайдера до начала разработки, не после.

**4. Изображения и производительность**

Mini App открывается в WebView — без нативного image caching. Каждое открытие = новые сетевые запросы на фото, если не настроен CDN с агрессивным кэшированием. Для бьюти-приложения с десятками фото работ это критично.

Обязательно: CloudFront / Cloudflare / аналог, WebP-формат, lazy loading, thumbnail preview.

**5. Telegram тема меняется динамически**

Пользователь может переключить тему прямо во время использования Mini App (системная тема Telegram подхватывается мгновенно). Если хардкодить цвета — половина пользователей увидит нечитаемый интерфейс.

Правило: использовать только CSS-переменные из `themeParams`: `--tg-theme-bg-color`, `--tg-theme-text-color`, `--tg-theme-button-color` и т.д.

---

#### Что работает хорошо в Telegram Mini App

**MainButton — лучший CTA в мобильном вебе**

`Telegram.WebApp.MainButton` — нативная кнопка внизу экрана, которую Telegram рендерит выше клавиатуры и home indicator. Она:
- Всегда видима (не скрывается при скролле)
- Следует теме Telegram автоматически
- Поддерживает `.showProgress()` для индикации загрузки
- Не конфликтует с клавиатурой (в отличие от CSS `position: fixed`)

Использовать для всех primary action: "Записаться", "Подтвердить", "Оплатить".

**HapticFeedback — делает приложение "нативным"**

```js
Telegram.WebApp.HapticFeedback.impactOccurred('medium') // тап по слоту
Telegram.WebApp.HapticFeedback.notificationOccurred('success') // подтверждение записи
Telegram.WebApp.HapticFeedback.notificationOccurred('error') // ошибка
```

Даже простое добавление haptic на ключевые действия резко повышает ощущение нативности. Пользователи не замечают этого сознательно, но чувствуют.

**initData для аутентификации без логина**

`Telegram.WebApp.initData` — подписанная строка с данными пользователя. На бэкенде верифицируется через `HMAC-SHA256` с bot token. Это полноценная авторизация без пароля, email и SMS.

Пользователь открывает Mini App — уже авторизован. Имя, аватар, Telegram ID — доступны сразу.

**BackButton — управляй историей навигации явно**

```js
Telegram.WebApp.BackButton.show()  // показать кнопку "назад" в шапке
Telegram.WebApp.BackButton.onClick(() => navigate(-1))
Telegram.WebApp.BackButton.hide()  // скрыть на root-экране
```

На каждом не-root экране — `BackButton.show()`. На главной — `BackButton.hide()`. Никогда не полагаться на браузерную историю.

**CloudStorage для лёгкого персистентного состояния**

`Telegram.WebApp.CloudStorage` — key-value хранилище, привязанное к пользователю, синхронизируется между устройствами. Идеально для: последний просмотренный мастер, избранные услуги, настройки уведомлений. Лимит: 1024 ключа по 4096 символов.

---

#### Что лучше не делать

| Антипаттерн | Почему проблема | Как правильно |
|---|---|---|
| `window.location.href` для навигации | Полная перезагрузка страницы, белый экран на 1–2 секунды | SPA с React Router / Vue Router |
| Кастомный шрифт через `@font-face` | +200–400ms к загрузке, мигание текста | Системный шрифт: `-apple-system, Roboto, sans-serif` |
| CSS `position: fixed` для CTA-кнопки | Ломается при открытии клавиатуры на iOS | Telegram MainButton |
| `100vh` для высоты экрана | Включает строку браузера, контент обрезается | `Telegram.WebApp.viewportStableHeight` |
| Свайп-карусель как основная навигация | Конфликтует со свайпом-закрытием Telegram | Vertical scroll + tabs |
| Alert / Confirm нативные | Выглядят как браузерные диалоги, не встроены в дизайн | `Telegram.WebApp.showPopup()` / `showConfirm()` |
| Хранить записи только в localStorage | Очищается браузером, не синхронизируется между устройствами | Бэкенд + CloudStorage для UI-состояния |
| Открывать внешние ссылки через `window.open` | Может быть заблокировано | `Telegram.WebApp.openLink()` / `openTelegramLink()` |

---

#### Рекомендуемый технологический стек

```
Frontend:   React (Vite) или Vue 3
Стили:      Tailwind CSS + CSS-переменные themeParams
Состояние:  Zustand / Pinia (лёгкие, не Redux)
Изображения: Cloudflare Images / Imgproxy (WebP на лету)
Backend:    Node.js (Fastify) или Python (FastAPI)
База:       PostgreSQL + Redis (кэш слотов)
Бот:        grammy (Node) или aiogram (Python)
Деплой:     Railway / Render / VPS с Caddy
Платежи:    Telegram Payments + ЮKassa / Тинькофф
```

### 10.4 Общий список рекомендаций

Сводный список из всех трёх точек зрения — что делать обязательно, что нельзя делать, и что даст максимальный эффект.

#### Обязательно сделать (must-have)

- [ ] `Telegram.WebApp.expand()` при старте — полноэкранный режим
- [ ] `BackButton` на каждом экране, кроме главного
- [ ] `MainButton` для всех primary CTA — не кастомные фиксированные кнопки
- [ ] Аутентификация через `initData` + верификация на бэкенде — без форм логина
- [ ] Предзаполнение имени клиента из `initDataUnsafe.user.first_name`
- [ ] CSS-переменные `--tg-theme-*` вместо хардкоженных цветов
- [ ] Skeleton loaders на всех экранах с сетевыми запросами
- [ ] WebP + lazy loading для всех изображений
- [ ] Haptic feedback на ключевых действиях (выбор слота, подтверждение)
- [ ] Telegram-бот для напоминаний (24ч и 2ч до записи) — единый бэкенд с Mini App
- [ ] Политика отмены видна ДО кнопки "Подтвердить"
- [ ] Цена и длительность на карточке услуги — всегда, без "уточните"
- [ ] Before/after фото в карточке каждой услуги
- [ ] Прогресс-индикатор booking flow (Шаг 1 из 3)
- [ ] Success screen с реферальным предложением сразу после записи
